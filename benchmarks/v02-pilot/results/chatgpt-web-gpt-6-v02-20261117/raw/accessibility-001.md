## 1. Scope, goal, and decision gate

**Page goal (inferred, not confirmed):** Enable people to review revenue trends and category breakdowns, use filters, complete the existing account-page form, and follow an AI observation's evidence-source link. This describes the interactions named in the case, not a verified business workflow. The page's exact goal, users, task priorities, navigation, copy, data, and visual design remain unknown.

**Known inputs:** A fictional analytics/account page; seven tester-reported defects; stakeholder desire for a modern, visually refined redesign; preference to reuse `TrendChart`, `PieChart`, `FilterDialog`, `TextField`, `Link`, and `LoadingIndicator`. No page source code or component API has been supplied; component names are known, but their implementations and existing reuse are not verified.

**Earliest unstable layer:** Accessibility behavior in reusable components and the page's integration of them. Preserve the existing content and underlying page structure; do not invent a new sitemap, page content, or visual design. Establish semantic and interaction contracts before visual polish. Follow **observe → identify problem → locate responsible layer → modify smallest reusable layer → validate**. Reuse/extend the six named components before contemplating new ones; address repeated visual defects at shared token level only when actual token use is known.

**Priority rule:** P0 = blocks keyboard access or focus containment/recovery for critical interaction; P1 = essential meaning, input identification, or evidence-link findability is inaccessible or unclear; P2 = nonessential decorative motion needs preference-aware behavior. The order is a proposed risk-based triage, **not** an assertion about measured severity, affected-user counts, or conformance criteria.

## 7. Delivery sequence, gates and validation checklist

1. **Discover/baseline:** Confirm reported symptoms in actual implementation; capture exact content, component reuse map, support matrix, and unknowns. Reported defects remain reports until reproduced. **Gate:** specific before-state evidence and responsible owners recorded.
2. **Systemize contracts:** Agree on the six component-level interaction/semantic contracts above; preserve current content and component boundaries. **Gate:** each change assigned to shared component versus page content/integration; no unjustified new components.
3. **Implement (separate future activity):** Fix dialog focus lifecycle and trend access first, then pie labels/equivalent, field name, source link label, and motion variant. **Gate:** unit/integration checks and accessible state review; no claim of completion in this artifact.
4. **Validate:** Run the manual/AT/visual matrix and automated checks; compare actual results against acceptance criteria; regression-test all known consumers. **Gate:** blockers resolved and documented evidence available, otherwise return to the responsible reusable layer.
5. **Explore/polish only after gates:** A modern visual treatment can refine layout, type, color and motion without suppressing labels, visible focus, descriptive links, non-color chart cues or reduced-motion behavior. **Gate:** rerun accessibility and content coverage checks after visual changes.

**Release-review checklist (all unchecked because no implementation or tests were supplied):**

- [ ] Actual current page content inventoried; nothing unintentionally changed or removed.
- [ ] P0 dialog and trend-chart issues reproduced, corrected and verified in keyboard/AT runs.
- [ ] Dialog initial focus, focus containment, close and focus restoration work on supported paths.
- [ ] Pie categories identifiable without color, with a usable accessible equivalent.
- [ ] Real visible/programmatic field label exists and matches intended field purpose.
- [ ] Evidence-source link text is understandable outside its paragraph and retains the actual destination.
- [ ] Reduced-motion loading treatment verified; any status remains available without distracting announcement loops.
- [ ] Focus visibility, contrast, reflow, zoom, touch and screen-reader checks performed across supported matrix.
- [ ] Automated findings triaged and manual failures resolved; shared-component regressions checked.
- [ ] Outcomes, evidence, outstanding issues, owners and decisions recorded; no unsupported WCAG conformance claim.
