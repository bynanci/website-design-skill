# v0.2 試點評分量表

[English](rubric.md) · 繁體中文

版本：`0.2-pilot.1`。本文件僅供評審使用；生成情境不可包含此文件或各案例的 `expected.md`。

此試點評估兩個選用案例的規劃交付物，共 18 項準則，滿分獨立為 **36 分**。它不改動凍結的 v0.1 40 分 benchmark、不產生官方 v0.1 分數，也不定義發布門檻。

| 分數 | 意義 |
|---|---|
| 0 | 缺少、矛盾、不安全，或輸出無法支持該項目。 |
| 1 | 相關但不完整，缺少重要行為或驗證步驟。 |
| 2 | 行為明確可行，並有針對該案例的驗收條件；證據界線清楚。 |

明確的驗收條件可得 2 分，不代表測試已執行。不得獎勵捏造的截圖、量測、使用者研究或符合性宣稱。每個非零分數須保留未修改輸出的原文摘錄；缺漏或零分則以註記說明。`completed` 僅代表生成與評分已完成，不表示全部準則通過。

## 響應式配置：18 分

| ID | 準則 | 2 分要求 |
|---|---|---|
| RL-01 | 內容完整 | 六個指定模組在寬/窄版均有對應，包含證據、聯絡資訊、觀察與列操作。 |
| RL-02 | 任務順位 | 客戶識別及可行動的觀察/證據/提問容易取得，輔助資訊順序有理由。 |
| RL-03 | 桌面取捨 | 不捲動視為偏好；取捨保留可讀文字與內容，並有審查 gate。 |
| RL-04 | 窄版圖表 | 明確圖例重排/揭露、保留五類與多序列語意，以及可及的數值/表格替代。 |
| RL-05 | 窄版表格 | 指定捲動/堆疊/明細策略，讓狀態、負責人、日期與操作可被發現。 |
| RL-06 | 輸入一致 | 圖表、證據、操作與揭露均有鍵盤/焦點、觸控與非 hover 路徑。 |
| RL-07 | 條件矩陣 | 列出 1920×1080、1366×768、390/320 CSS px、200% zoom 與窄容器，並區分候選斷點與量測。 |
| RL-08 | 元件節制 | 明確重用/擴充指定元件；新增責任有可重用理由。 |
| RL-09 | 證據誠實 | 區分提供的缺陷、提案行為，以及未驗證的渲染/裝置/可及性結果。 |

重大錯誤另外記錄：

- `required-content-hidden`：為了塞入版面而刪除或隱藏必要資訊/操作。
- `hover-or-color-only`：圖表語意或必要操作仍只透過 hover/顏色提供。
- `unsupported-success-claim`：沒有證據卻宣稱量測、渲染、裝置或符合性成功。

## 可及性：18 分

| ID | 準則 | 2 分要求 |
|---|---|---|
| AX-01 | Tooltip 存取 | 鍵盤/焦點路徑、固定顯示或表格替代，以及具體檢查。 |
| AX-02 | 圖表語意 | 不只靠顏色辨識類別，並檢查 theme/色覺下的語意保留。 |
| AX-03 | 對話框焦點 | 焦點放置、適用的限制範圍、Escape/關閉與回到觸發器均有檢查。 |
| AX-04 | 欄位標籤 | 真正的可見/程式標籤與 TextField 關聯，不能用 placeholder 取代。 |
| AX-05 | 動態/狀態 | 減少動態時保留載入/狀態資訊，並有偏好設定檢查。 |
| AX-06 | 連結名稱 | 證據來源連結在情境中具有有意義的可及名稱。 |
| AX-07 | 共用層級 | 修正位於既有共用元件/token 層，責任歸屬有理由。 |
| AX-08 | 驗證方式 | 逐項列出鍵盤/人工/螢幕閱讀器檢查，不能只泛稱執行 audit。 |
| AX-09 | 證據界線 | 區分回報缺陷、疑似原因、提案修正，以及缺少的瀏覽器/對比/符合性證據。 |

重大錯誤另外記錄：

- `missing-keyboard-path`：提案仍未處理提供的 hover-only 或 mouse-only 缺陷。
- `missing-dialog-focus-recovery`：省略對話框焦點處理/復原，或宣稱套件自動保證。
- `unsupported-conformance-claim`：沒有證據卻宣稱可及性符合或 audit 通過。

總分不可抵銷重大錯誤。準則分數、重大問題與證據缺口須一起呈現。若獨立乾淨執行出現相同重大錯誤，保留原始輸出、檢查跨平台契約，並記錄版本決策後重跑；不可用產品專用提示詞掩蓋失敗。

## 評審順序

1. 評分前確認固定來源、身份、能力與隔離紀錄。
2. 開啟評審材料前，先保留生成的原始 bytes 及 SHA-256。
3. 生成完成後才能讀取該案例的 `expected.md` 與此量表。
4. 逐 ID 評分、保存原文依據、另外記錄重大錯誤。
5. 接受紀錄前執行 `python3 scripts/validate_v02_pilot.py`。
6. 比較至少兩個合格的獨立執行情境；runner 不可用必須另外呈現。

這批基礎設施不包含真實已完成的執行。單元測試中的紀錄是合成測試資料，絕不可提交為 agent 證據。
