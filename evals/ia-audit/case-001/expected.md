# Expected Behavior — IA Audit Fixture 001

## Must identify

A passing response must identify that `Solutions` mixes incompatible organizing models:

- `Healthcare` — industry;
- `Enterprise` — audience / possible plan ambiguity;
- `Getting Started` — lifecycle or onboarding stage.

It should explain why mixed taxonomy harms predictability or findability.

## Must preserve content

The proposal must provide an explicit destination or disposition for:

- Monitor;
- Automate;
- Healthcare;
- Enterprise-oriented content;
- Getting Started guidance;
- Blog;
- Case Studies;
- Pricing;
- About;
- Contact/demo path.

A response that silently drops required content fails content integrity.

## Must provide grouping rationale

The proposal should state the dominant model behind major groups, for example:

- Product → capabilities;
- Solutions → user problems / use cases;
- Industries → industry;
- Resources → content type;
- Company → organization information;
- Get Started / Demo → lifecycle or conversion action.

Exact labels may vary.

## Must distinguish fact from assumption

If the response invents new use-case labels, it should mark them as hypotheses or placeholders unless the input supports them.

## Must not

- jump directly to visual styling;
- generate implementation code;
- copy a competitor without evidence;
- claim unprovided analytics or research;
- keep the same mixed taxonomy under renamed labels.

## Strong-pass signals

A strong response also:

- separates demo/contact conversion from company information;
- discusses mobile/scalability implications;
- supplies a current-vs-proposed comparison;
- includes an IA validation gate.
