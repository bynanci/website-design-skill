# 網站改版工作流程

[English](workflow.md) · 繁體中文

本文件補充 SKILL.md 使用的核心工作流程。

## 1. 探索

蒐集或推估下列資訊，並明確標示未知項目：

- 商業目標；
- 主要使用者與使用者任務；
- 現有站點地圖與導覽；
- 內容清單；
- 可取得的分析或行為證據；
- 品牌、技術、可及性與利害關係人限制；
- 成功條件。

資訊不足時仍可推進。記錄缺口，並相應降低結論信心。

## 2. 組織

盤點目前資訊架構，檢查主導覽、次導覽、頁面層級、重複目的地、模糊標籤、混用分類法、孤立頁面、過深層級與不一致的分組邏輯。

對每個主要群組，指出它採用的心智模型，例如產品、使用者目標、產業、使用情境、受眾、生命週期階段或內容類型。沒有明確理由時，不要混用不同模型。

### 競品與參考案例

參考相關競品或鄰近領域案例以擷取原則，不複製外觀。將觀察分為常見模式、有用模式、差異化模式與應避免模式。

整理脈絡：

現有 IA + 使用者任務 + 內容清單 + 市場觀察 + 商業目標 → 提案 IA

確認 IA 前，檢查目的地是否可預期、分類邏輯是否清楚、重複項目是否已處理、標籤是否不依賴公司內部知識、結構是否可擴充，以及手機版能否延續相同心智模型。

## 3. 線框

先處理影響最大的頁面。每頁定義目標、受眾、回答的問題、區塊順序、CTA 層級、內容需求與候選元件模式。

鎖定線框前先完成內容涵蓋矩陣。內容狀態可為保留、改寫、合併、搬移、刻意移除或缺漏。每個非預期的缺漏都必須先處理。

## 4. 視覺探索

使用相同的結構基準比較多個視覺方向，檢查字體、間距、網格、色彩邏輯、影像、資訊密度、容器/邊框、互動與動態效果。

將主觀回饋轉成可調整的設計變數。例如「太制式」可能代表對稱過於僵硬、卡片太密、字體太傳統、圖片不足或色彩保守。

## 5. 建立系統

整理設計原則、token、可重用版型、元件契約與變體、互動狀態及響應式規則。

每個可重用元件應定義用途、內容模型、變體、狀態、響應式行為、互動、可及性與組合規則。避免產生大量近似元件。

## 6. 實作

實作前，先將每個線框區塊對應至既有模式或元件。對應動作依序為重用、擴充、變體、組合、新建。先建立必要的共用 primitive，再放入頁面，除非改版明確包含架構遷移，否則沿用既有專案慣例。

## 7. 驗收

### 資訊架構 gate
- 分類容易理解，標籤清楚；
- 導覽深度合理，沒有非預期重複目的地；
- 結構可擴充，手機導覽可行。

### 線框 gate
- 頁面目標明確，內容層級連貫；
- CTA 層級清楚，必要內容齊全；
- 區塊順序有意圖。

### 視覺 gate
- 樣式符合品牌定位；
- 字體層級一致、資訊密度恰當；
- 不靠裝飾也能理解版面；
- 視覺系統能擴展到多頁。

### 系統 gate
- token 一致、元件責任清楚；
- 變體受控，響應式行為有定義；
- 相近元件已合併或說明差異。

### 實作 gate
- 內容涵蓋完整、重用方式已檢視；
- 響應式與可及性已檢查；
- 沒有重大視覺回歸、意外內容遺失或多餘的一次性樣式。

## 迭代原則

觀察 → 找出問題 → 定位責任層級 → 修改最小的可重用層級 → 驗收。

可處理的層級包括內容、資訊架構、導覽、線框、設計模式、元件、token、頁面組合與實作。
